# このゲームを作る／育てる上で気にすべきこと

「英単語ならべ」（英単語ならべかえPWA）のような、**子ども向け・語順パズル型・英語学習・PWA** ゲームを開発・改修する際に検討すべき論点のメモ。将来のセッションで参照する目的で残す。実装済みの箇所は該当ファイルを添え、未対応/要検討の箇所は理由とセットで書く。

対応済みの項目には ✅ とPR番号を付けている。このドキュメント自体も見直すたびに更新すること。

## 1. ゲームデザイン・バランス

- ✅ (#32) **スコアリングの公平性**: 旧実装の `timeBonus = timeLeft * 2` は、制限時間が長いレベルほどボーナスの上限が大きくなる（英検4級は最大+52、英検2級は最大+38）という逆転を起こしていた。問題が難しくなるほど速さの見返りが減る形になっていたので、`timeBonus(timeLeft, timeLimitSec)`（`src/utils/scoring.ts`）に置き換え、「制限時間のうち何割を残したか」に比例した `MAX_TIME_BONUS`（50点）までの配点にした。同じ相対速度なら、レベルにも文の長さにも関係なく同じ点が入る。基礎点100・コンボ倍率は従来どおり。
- ✅ (#8) **ライフ制のプレッシャー**: 残機切れで即終了する問題は、タイマー・ライフなしの「練習モード」（設定モーダルの🧪練習モード）を追加して緩和した。ベストスコアには反映しない。残機は現在 `START_LIVES = 10`。
- ✅調査済み（対応不要）**出題プールの枯渇**: 実測値は eiken4: 341, eiken3: 239, eikenPre2: 248, eiken2: 210, koukoNyushi: 562（計1,600問）。1セッション10問なので、素朴に繰り返し遊んでも暗記ゲー化するほど早くは枯渇しない。加えて (#11) の復習出題も全体からすれば少数を優先的に混ぜるだけなので、プール自体の拡張は現時点では不要と判断。
  - ✅ (#32) ⚠️ (#28) の「エンドレス」で前提が変わっていた。補充時の重複排除がキューに残っている問題に対してのみで、**すでに出題済みのIDを保持していなかった**ため、1回の run が210問を超えると（英検2級が最短）重複が出始めていた。`GameScreen` に `servedIds`（run 中に出題した全IDの `Set`）を持たせ、補充時にこれで除外するようにした。プールを完全に使い切ったら `servedIds` をキュー中の分だけにリセットして周回を続ける（補充が空になって進行が止まらないように）。
- ✅ (#28) **プレイ時間の選択肢**: タイトルの開始ボタンを「10問チャレンジ」（従来の固定10問）と「エンドレス」（ライフ切れ、またはHUDの「やめる」まで出題しつづける）の2つに分けた。エンドレスは30問ずつ先読みでキューを補充する（`ENDLESS_BATCH` / `ENDLESS_REFILL_AT`）。
- ✅ (#30) **ベストスコアがモード間で不公平**: ベストスコアと★はレベル単位で両モード共通の1レコードのまま。ただし比較を生スコアから `normalizedScore()`（1問あたりに割ってから10問分に戻した「10問換算スコア」）に変えた（`src/utils/scoring.ts`）。10問チャレンジの換算スコアはその run のスコアそのものなので、既存の記録も表示・順位づけとも変わらない。長く走っただけのエンドレスは勝てなくなる。★は従来どおり `MIN_RANKED_QUESTIONS`（10問）未満を0にして、1問だけ解いて やめる で★3を取る抜け道を塞いである。レベル選択カードは換算値を表示し、記録の出所がエンドレスの場合のみ「∞ N問を10問換算」を添える。結果画面もエンドレスのときだけ換算値を出す（生スコアが大きいのに記録更新されない理由が分かるように）。
- ✅ (#30) **成長記録の計上漏れ**: 旧実装は `recordMissedOnly()` を `resolve()` の中で `isLastQuestion || outOfLives` のときだけ呼んでいた。そのため **一発勝負モードで最終問題以外を間違えると、その問題は成長記録にまったく計上されない**（ライフ切れ経路と、エンドレス で やめる を押した場合も同様）という取りこぼしがあった。集計方法を変更し、`GameScreen` がセッション中の各問題の最新状態を `questionOutcome: Map<string, 'missed' | 'recovered'>` で持ち、セッション終了時に `'missed'` のまま残っているものを数えて `recordMissedOnly(count)` を1回だけ呼ぶようにした。エンドレスで一度克服した問題が再出題されて再び間違えるケースも正しく扱える。これで `firstTry + recovered + missedOnly === totalAnswered` が常に成立する。
- ✅ **難易度カーブ**: レベル内の出題順が完全ランダムなため、難しい構文が1問目に来ることがあった。`warmUpFirst()`（`src/data/questions.ts`）で、run の最初の出題（10問チャレンジ・エンドレスの最初の補充・復習・間違えた問題のやり直し）を引いた中で一番短い文（タイル数最少。制限時間も語数で決まるので、短い＝易しいの目安として使える）にして、まず1問解けた状態から始められるようにした。残りの順番はランダムのまま。全体を易→難に並べると、ライフが減った終盤にいちばん難しい問題が集まるので、そこまではしていない。文法練習は対象の文法から始まる独自の並びなので対象外。
- ✅ (#32) **タイムリミットが難易度と逆行していた**: 旧実装は `src/data/levels.ts` にレベルごとの固定 `timeLimitSec` を持ち、レベルが上がるほど短くなる（26秒→19秒）一方で文は長くなる（平均5.2語→8.2語）ため、**1語あたりの持ち時間が5.03秒→2.30秒と2.2倍厳しくなる二重の締め付け**になっていた。同一レベル内でも5語と12語が同じ秒数を共有していた。`timeLimitSec` を `secPerWord` に置き換え、`src/data/timeLimit.ts` の `timeLimitFor(level, wordCount)` = `BASE_TIME_SEC`(7秒) + `secPerWord` × 語数 で問題ごとに算出するようにした。`BASE_TIME_SEC` は「日本語を読んで構文を決める」文長に依存しない部分、`secPerWord` がレベルの難易度ダイヤル（3.6→3.0→2.6→2.3、高校入試2.4）。結果、1語あたりは 6.00〜4.50秒（英検4級）〜 3.80〜2.92秒（英検2級）に収まり、勾配は残しつつ逆転は解消した。
  - ✅ (#32) **実質クリア不能な長文の混入**: 高校入試バンクに **21語の問題が2問**あり、旧20秒固定では0.95秒/語で物理的に解けなかった（21タイルはスマホ横画面のトレイにも収まらない）。`src/data/questions.ts` に `MAX_WORDS_PER_QUESTION`（12語）を追加し、バンク組み立て時に超過分を除外した。除外は562問中8問のみで、プールは554問残る。タイル配置が長文に対応できるようになったら定数を上げるだけでよく、データ自体は消していない。667×375（iPhone SE横）で11語問題までトレイがはみ出さないことをPlaywrightで確認済み。

## 2. 教育効果・コンテンツの正確性

- **英文の文法的正確性**: テンプレート×語彙の組み合わせで不自然な文・文法誤り（三単現のs、冠詞、時制の一致など）が生成されないか、ネイティブチェック/自動検証が重要。
  - ✅ `src/data/grammarValidation.ts` + `grammarValidation.test.ts` を追加し、全レベルの問題バンクに対して構造面のサニティチェック（先頭大文字・終端句読点・二重スペース/連続同一単語・`${...}`のようなテンプレート展開漏れ）をCIで自動検証するようにした。ただし三単現のsや冠詞・時制の一致のような意味的な文法正しさまでは検証できておらず、そこはネイティブレビューに頼る必要が引き続きある。
  - ✅ **一致の検証を追加**: 品詞表（`src/data/pos.ts`）を使い、取りこぼしても誤検出しない範囲で2つの規則を足した。(1) 文頭・接続詞やカンマの直後の he/she/it に原形の動詞が続く（"He play"）。put/cut など過去形が原形と同じ動詞と、不規則な過去形（`IRREGULAR_PAST`）は除外。(2) 助動詞・do/does/did（＋代名詞）の後に -s/-ed 形や不規則な過去形が来る（"can plays" "Did you went"）。名詞にもなる語（plays など）は、文頭の助動詞の直後だけは主語の名詞として読めるので見逃す（"Will students come?"）。既存の全バンク（約1,600文）は誤り0件で通った。冠詞と名詞の数の一致（"a books" "many book"）も試したが、fish/sheep・this bus・a glass のような誤検出ばかりで実際の誤りは無かったので入れていない。時制の一致（yesterday と現在形など）は未対応。
- ✅ (#4) **誤答時のフィードバックの薄さ**: 不正解時にも `question.note`（文法解説）を表示するようにした（従来は正解時のみ）。
- ✅ (#6) **どこが間違っていたかの可視化なし**: 誤答時、`question.words[i]` と一致しないスロットに赤枠のミスマッチ表示を追加した（`WordTile.tsx` の `AnswerSlot` `mismatch` prop）。
- ✅ (#11) **スペースドリピティション不在**: `src/utils/reviewQueue.ts` を追加し、レベル単位で誤答した問題id（当初は最大30件。のちに200件へ拡大）を`localStorage`に記録。`pickQuestions()` の `priorityIds` 引数でセッションに優先的に含めるようにした（専用UIは追加せず、出題の裏側だけを調整するシンプルな方式を選択）。正解すると記録から外れる。
  - ✅ 単なる「誤答リスト」から軽量SM-2方式の間隔反復に強化。誤答した問題は次回すぐ出題対象になり（`step:0`）、復習で正解するたびに 1日→3日→7日→14日 と出題間隔が広がり、最後まで抜けると（マスター済みとして）キューから外れる。誤りをまた重ねると `step:0` に戻る。`loadDueIds()`/`recordCorrect()`/`recordMiss()`（旧 `loadMissedIds`/`recordMastered`）で日時ベースの `dueAt` を管理。旧フォーマット（文字列配列のみ）のデータも移行して読み込む。
- ✅ **文法タグを学習に使っていなかった**: #32 で全問に `grammar` タグを付けたが、画面からは一切参照されていなかった。次の3つで使うようにした。
  - **苦手な文法の見える化**: `src/utils/grammarStats.ts` に「レベル×文法」単位の正答数/出題数を記録（`wordrush.grammar`）。1問につきセッション内の**最初の結果だけ**を数える（あとで直せても、その時点で身についていたかの指標にはならないため）。成長記録画面に、`MIN_ATTEMPTS_FOR_RANKING`（3問）以上解いた文法のうち正答率が低い順に最大5件を「にがてな文法」として出す。レベル単位で持つのは、練習ランがレベル（制限時間・問題プール）に縛られるため。
  - **文法ごとの練習**: 「にがてな文法」の各行の 練習する から、そのレベル×文法の問題だけで最大10問のランを始められる（`FocusSession` の `kind: 'grammar'`）。
  - **復習を文の暗記から文法の定着へ**: `pickQuestions()` は、復習対象の問題1問ごとに**同じ文法タグの別の文**を1問ペアで混ぜるようになった。同じ文を繰り返すだけだとタイルの並びを覚えて通過できてしまうため。復習が多すぎて入りきらないときもペア単位で入るので、1セッションに入る復習対象の問題数は従来の約半分になる。
- ✅ **学習効率: 復習・苦手文法に時間を寄せる**
  - **復習が「たまたまそのレベルを選んだとき」にしか出なかった**: 間隔反復キューはレベル単位で、期日が来た問題もそのレベルを選ばない限り出題されず、期日が来ていることも画面のどこにも出ていなかった。間隔反復は期日どおりに解いてはじめて効くので、タイトル画面に「📚 復習 N問」（全レベル合計。0問なら無効化）を出し、そこから復習するレベルを選んで**期日の来た問題とその同じ文法の兄弟問題だけ**を最大10問解く復習ラン（`FocusSession` の `kind: 'review'`、`pickReviewQuestions()`）を追加した。通常のレベル選択カードにも「📚 復習 N問 たまってるよ」を添える。他の練習ランと同じくベストスコアは更新しない。結果画面の再挑戦ボタンは、まだ期日の問題が残っていれば「つづけて復習 (N問)」、なければ「ほかのコースを復習」（復習用のレベル選択へ）になる。
  - **通常ランの出題が文法の得手不得手を見ていなかった**: 復習枠以外はプールからの一様ランダムで、もう身についた文法にも苦手な文法と同じだけ時間を使っていた。`grammarWeights(levelId)`（`src/utils/grammarStats.ts`）で文法ごとの抽選の重みを出し、`pickQuestions()` の残り枠を重み付きシャッフル（Efraimidis–Spirakis）で選ぶようにした。重みは直近の正答率に対して線形で、全問不正解が `WEAKEST_GRAMMAR_WEIGHT`（2）、全問正解が `MASTERED_GRAMMAR_WEIGHT`（0.4）。解答が `MIN_ATTEMPTS_FOR_RANKING`（3問）未満のうちはその少なさに応じて中立（1）に寄せる。まだ解いたことのない文法は `UNSEEN_GRAMMAR_WEIGHT`（1.3）で少しだけ優先し、復習や苦手に押されて新しい文法が出てこなくなるのを防ぐ。復習枠（期日の問題とその兄弟）は重みに関係なく必ず入る。
  - **にがてな文法が一度苦手になると抜けにくかった**: 文法の正答率が生涯累計だったため、あとで身についても初期の誤答が残り続け、「にがてな文法」から外れるにも、上の重み付けが下がるにも、過去の誤答を上回るほど正解を重ねる必要があった。正答率を直近 `RECENT_WINDOW`（10問）で判定するようにした（生涯の解答数は `totalAttempts` として残す）。成長記録の表示も「直近 x/y問」に変えた。旧フォーマット（累計のみ）の記録は順序が分からないので、同じ正答率で最大10件の直近履歴を組み立てて移行する。
- ✅ **学習効率: 間違えた問題・迷った問題の扱い**
  - **復習キューが30件で黙って切り捨てられていた**: 間隔反復キューはレベルごとに `MAX_TRACKED`（30件）を超えると古い誤答から捨てていた。苦手な子なら3回遊べば超える数で、捨てられた問題は二度と復習に出なかった。`MAX_TRACKED` を200件に上げた（`src/utils/reviewQueue.ts`）。
  - **間違えた問題は正解を見せて次へ進むだけだった**: 不正解（時間切れを含む）のあとは、正解の英文を表示したまま**自分で正しい順に並べ直してから**次へ進むようにした（`GameScreen` の `status: 'rebuild'` → `'rebuilt'`）。違う単語は弾かれるだけでペナルティなし、タイマーなし、得点・記録なし。正解を見るだけでは「見て分かる」止まりで、自分で組み立てるのが練習になるため。即時判定モードの `'fixed'`（一語ずつ直して完成させた）は、すでに並べ終えているので対象外。ライフ切れで終わるときもやらない。
  - **間違えた問題をその場で解き直す機会がなかった**: 間違えた問題（`'wrong'` / `'fixed'`）を、`RELEARN_GAP`（3問）あとに同じランの中で「🔁 もう一回」として出し直す（`src/utils/relearn.ts` の `insertRelearn()`）。間に別の問題を挟むことで、直前に見た答えを写すのではなく思い出す練習になる。10問チャレンジ・練習ランは1ランあたり `MAX_RELEARN_PER_RUN`（5問）まで、エンドレスは上限なし。出し直しは各問題1回だけ。**出し直した問題は採点しない**: 得点・コンボ・ライフ・正解数・問題数（`N / 10` の表示と結果画面の分母）には入らず、HUDは「🔁 もう一回」になる。正解すれば成長記録で「間違えてから正解」に数える。復習キューは動かさない（数問前に答えを見た直後の正解は、間隔を広げてよい根拠にならないため）。
  - **迷って正解した問題が復習に入らなかった**: 間隔反復キューは不正解だけが入口だったので、制限時間ぎりぎりや何度も並べ直してやっと正解した問題はそのまま忘れられていた。`isShakyAnswer()` で、制限時間の `SHAKY_TIME_RATIO`（75%）以上を使った、または解答欄からタイルを戻した回数（スロットのタップ・全て戻す）が `SHAKY_REMOVALS`（2回）以上の正解を「迷った正解」とし、`recordShaky()` でキューに入れる。キューにない問題は step 1（翌日）から、キューにある問題は間隔を広げずに今の間隔をもう一度。練習モード（タイマーなし）は戻した回数だけで判定する。得点や正解数は通常の正解と同じ。画面には「📚 ちょっと迷ったね。あとで復習に出すよ」と出す。
- ✅ **学習効率: 第二言語習得の理論からの見直し**
  - **日本語からの置き換えしか練習していなかった**: 出題は必ず日本語から始まるので、英語を英語のまま聞いて処理する練習（インプット仮説）がなかった。設定に「👂 出題のしかた」を追加し、**🎧 英語を聞いて**（`listeningMode`、`wordrush.listeningMode`）では日本語を隠し、問題の開始時に日本語の代わりに英文を読み上げる（読み上げが終わってからタイマーが動くのは日本語のときと同じ）。日本語は答えたあと（または下のヒントが出たとき）に表示する。音声OFF・TTS非対応の環境では聞くものがないので、自動で日本語出題に戻る。難しくなる方向の変更なので、ベストスコアは通常どおり記録する。
  - **間違えたときに答えしか手がかりがなかった**: やり直しモードで間違えた単語を置いたとき、英文の読み上げと同じタイミングで「💡 ヒント: 文法名」（`grammarLabel(question.grammar)`、タグがなければ `note`）を出すようにした。正解をそのまま示す前に、どの文法の文かという手がかりを出して本人に直させる（訂正フィードバックでいう、正解を言い直して見せる方式より、自分で直させる方式のほうが定着しやすい）。聞いて並べるモードでは、同じタイミングで日本語の意味も出す。一発勝負モードは間違えた時点で正解を表示するので対象外。
  - ❌ 検討して見送り: **語形の違う紛らわしいタイルを混ぜる**（`go/goes/went` など）は、語形変化を問う問題になり並べ替え問題の趣旨から外れるので採用しない。**文法の段階を追った出題**は、レベルでもう出題範囲をある程度絞っているので不要と判断。
- ✅ **学習効率: 語句整序そのものの見直し（第二言語習得の観点から・その2）**
  - **間違いの赤枠が「どこがずれたか」を教えていなかった**: 赤枠は「同じ位置の語が正解と違うか」で付けていたので、1語をずらして置くとその後ろが全部赤になり、本人には「ほとんど間違えた」としか見えなかった。`misplacedSlots()`（`src/utils/answerCheck.ts`）で、置いた並びと正解の最長共通部分列をとり、そこから外れた（動かす必要のある）タイルだけに赤枠を付けるようにした。`How cats do you have many` なら `many` だけが赤くなる。誤りのどこに気づけるか（noticing）で伸び方が変わるので、ずれた語に目を向けさせる。
  - **文末の記号が最後の語を教えていた**: `.`/`?`/`!` が最後の語のタイルに付いていたので、最後に来る語は考えなくても分かり、実質的に1語少ない問題になっていた。記号はタイルから外し（`splitFinalPunct()`）、解答欄の後ろに固定で表示する。文の途中の `Mr.`・`Mt.` の点はそのまま。
  - **正しい別の語順を不正解にしていた**: 判定は正解文との完全一致だけで、`I cleaned my room yesterday.` を `Yesterday I cleaned my room.` と並べると不正解になっていた（上の記号のせいで実際には作れなかったが、記号を外すと作れるようになる）。文法的に正しい文を不正解にすると「時の副詞は文末にしか置けない」という誤ったルールを教えてしまうので、文末の時の語句（`yesterday`・`today`・`tomorrow`・`tonight`・`last/next/every 〜`・`this morning` など・`on 曜日`）は文頭に置いても正解にする（`frontableTimePhrase()` / `acceptedOrders()`）。対象は、代名詞や限定詞の主語で始まる平叙文で、ほかの節や不定詞がない文に絞った。`This is the pen I bought yesterday` や `I wish I had studied harder last year` のように時の語句が後ろの節にかかる文、`since last year` のように前置詞に続く語句は動かさない。全2,757問のうち、重複を除いて164文に別解が付く（全件を目で確認済み）。
    - 一発勝負モードは受けつける並びのどれかに一致すれば正解。即時判定モードは「埋まっている欄が、どれかの正解と矛盾しないか」で1語ずつ判定する（途中の欄を外して入れ直すことがあるので、先頭からの一致ではなく欄ごとに見る）。赤枠は、受けつける並びのうち近いほうと比べる。間違えたあとの並べ直しと「正解:」の表示は書かれた文のまま。
    - 熟語をひとまとまりのタイルで出しているときは、タイルの境目で動かせる場合だけ別解を付ける。
  - **文法ごとの練習が同じ文法の連続だった**: 10問とも同じ文法だと、途中から型を見分けずにくり返すだけで解けてしまう。「にがてな文法」から始める練習ランは、最初の `GRAMMAR_BLOCKED_LEAD`（3問）をその文法だけにして型をつかませ、そのあとは1問おきに**紛らわしい文法**（日本語は似ているが語順が違うもの）の問題を混ぜる（10問中3問）。組み合わせは `src/data/grammar.ts` の `CONTRAST_GROUPS`：後置修飾（分詞・関係代名詞・前置詞句）、現在完了と過去形、too 〜 to / enough to / so 〜 that、比較、不定詞の用法、目的語 + to do と使役、SVOO/SVOC、疑問文と間接疑問、動名詞主語と It is 〜 to、受動態と過去分詞の後置修飾、仮定法。交互に解かせる練習（interleaving）で、どの構文を使うかを毎回選ばせる。そのレベルに紛らわしい文法の問題がなければ従来どおり全問その文法。対象の文法の問題が10問に満たないときに、紛らわしい文法でランを水増しすることはしない。混ぜた問題は、それぞれ自分の文法の成績として記録される。
  - **学習の効果を確かめる数字がなかった**: 間隔反復の期日が来て出題された問題を、そのランで最初に解いたときに正解できたかを、復習の段階ごとに `wordrush.retention` に記録する（`recordReviewRecall()`）。期日前に出た問題や、キューに入っていない問題は数えない。成長記録画面に「🧠 復習で思い出せた割合」（間違えた次の回／1日あけて／3日あけて／7日あけて／14日あけて）を出す。7日・14日で大きく下がるなら間隔が広すぎ、どこもほぼ100%なら広げてよい、という `REVIEW_STEP_DAYS` を調整する根拠にする。記録のリセットで一緒に消える。
  - ~~見送り~~ → 下の「その3」で対応した: 句をひとまとまりのタイルで出す足場かけと、日本語話者に多い語順の誤りを見分けるヒント。
- ✅ **学習効率: 語句整序そのものの見直し（その3）**
  - **品詞表**: 名詞句を見つけたり語順の誤りを見分けたりするために、問題に出てくる語（1,586語）の品詞を CEFR-J Wordlist から引いた表 `src/data/posLexicon.generated.ts` を作った。`npm run pos:generate`（`scripts/pos-lexicon.ts`）で作り直す。活用した語は語彙点検と同じ原形戻し（`scripts/vocab-audit/lexicon.ts`）で引き、語尾で品詞を絞る（`played` は動詞だけ、`bigger` は形容詞だけ、不規則変化の `went` は動詞だけ）。リストにない語（人名など）は表に入れず、「何でもありうる」として扱う。問題を足したのに作り直していないと `scripts/pos-lexicon/posLexicon.test.ts` が落ちる。
  - **句をひとまとまりのタイルで出す（処理可能性理論）**: 学習者は句の中の語順を先に処理できるようになり、句どうしの順番はそのあとになる。受動態や関係詞のような節の組み立てが要点の文で、`the` が `station` の前に来ることまで同時に考えさせると負荷が高い。そこで、そのレベルのその文法の直近の正答率が `PHRASE_CHUNK_BELOW`（60%）未満（3問以上解いたうえで）の間だけ、文の中の単純な名詞句（限定詞 + 形容詞0〜2語 + 名詞。`the station`・`my little sister`・`a red umbrella`）を1枚のタイルで出し、「🧩 ことばのまとまりを1枚のカードにしているよ」と添える（`src/utils/phraseScaffold.ts`、`src/data/nounPhrases.ts`）。正答率が戻ると語に分かれる。
    - 誤ったまとまりを作らないよう慎重にしている: 名詞は名詞にしかならない語に限る（`book`・`park` のように動詞にもなる語は拾わない）、後ろに名詞が続く（`the tennis club`）・`of` が続く（`a lot of`）句は拾わない、`gave her books` のような二重目的語の `her` は所有格とみなさない、`that` は接続詞のことが多いので限定詞に入れない。全問で見つかった句を目で確認済み（1,509問に何らかの句がある）。
    - 句の中の語順そのものが要点の文法（冠詞・形容詞・複数形・代名詞・分詞の前置修飾・比較全般・数量表現・Whose / Which / How many / How much・感嘆文・最上級 + 現在完了）では出さない。6語未満の文と、まとめるとタイルが4枚未満になる文もそのまま。熟語と重なる句はまとめない。
  - **日本語話者に多い語順の誤りを見分けてヒントを出す（母語の転移）**: 日本語は動詞が最後・助詞が名詞のあと・説明が名詞の前に来るので、日本語の語順に頼ると決まった誤りが出る。置いた並びが正解から最初にずれた位置で、本来来るタイルと代わりに置いたタイル（本当はもっと後ろの語）の品詞・文法から、次の5つを見分ける（`src/data/orderHints.ts`）。
    - 疑問文で主語を助動詞より前に置いた → 「疑問文は Do / Is / Can などを主語の前に置くよ」
    - 間接疑問で疑問詞のあとに動詞を先に置いた → 「文の中の疑問は『疑問詞 → 主語 → 動詞』の順」
    - 後置修飾の文で説明の語を名詞の前に置いた → 「名詞をくわしく説明することばは、名詞のうしろに置くよ」
    - 前置詞より先に名詞を置いた → 「in / at / to などは名詞の前に置くよ（日本語の「〜で」「〜に」とは逆）」
    - 動詞より先に目的語などを置いた → 「英語は『だれが → どうする → 何を』の順。動詞を先に置こう」
    - 即時判定モードでは間違えたタイルを置いた時点で、ふだんの「💡 ヒント: 文法名」の横に「🔎 …」で出す。一発勝負モードでは採点後、正解の下に出す。はっきりしないときは何も出さない。全問について「ある位置に後ろの語を置いた」場合を総当たりで流し、誤判定を見ながら条件を絞った（`last week` の `last` を動詞とみなさない、不定詞の `to` を前置詞とみなさない、`doing` は動く助動詞ではない、熟語の中は対象外、など）。
  - **文頭の大文字ヒントを初期設定で OFF にした**: 文頭の大文字は、文末の記号と同じく「最初に来る語」を教えてしまう。設定の初期値を OFF にした（すでに設定を保存している人の設定はそのまま）。
  - **大文字 OFF のときに `i'm`・`tom`・`kyoto` と表示されていた**: 最初の語を機械的に小文字にしていたため、`I` 以外の常に大文字の語まで小文字になっていた。`keepsCapital()`（`src/data/capitalization.ts`）で、`I` とその短縮形（`I'm`・`I'll`）、文の途中でも大文字で出てくる語（`Kyoto`・`English`・`Mr.`）、文頭にしか出てこない固有名詞の一覧（`SENTENCE_INITIAL_PROPER_NOUNS`）は大文字のまま残す。`May` は次の語が主語の代名詞なら助動詞（`May I …?`）として小文字、そうでなければ月として大文字。
  - 見送り: 文の途中のカンマもタイルに付いたまま（`Yes,`・`When I got home,` の149問）。位置の手がかりにはなるが、外すと節の順番を入れ替えた別解も受けつける必要があるので現状維持とした。
- ✅ **学習効率: もう解ける文に時間を使っていた**
  - 通常ランの出題は「期日の来た復習」と「文法ごとの重み」で決めていて、**文そのものを前に解けたか**は見ていなかった。そのため、すらすら解けた文も次のランでふつうに引かれ、1ランの枠をもう身についた文に使ってしまううえ、タイルの並びを覚えていて文法を考えずに通過できてしまっていた。

  - 練習ラン（文法・間違えた問題）は問題を選んで出しているので、ランダム出題とは条件が違う。そのため**ベストスコアは更新しない**。星も出さない（10問未満だと必ず0になるため）。成長記録・復習キュー・文法の集計には通常どおり反映する。
- ✅ **即時判定モードで間違えた単語を置いたときに英文を再生**: 間違えた時点で正しい英文をまるごと読み上げ、次の語を聞いて判断できるようにした（SFXオン時のみ）。続けて間違えても、読み上げ中は最初からやり直さない。タイマーは止めない（聞くヒントは使った分だけ時間がかかる、というコスト付き）。一発勝負モードは置いた時点で正誤が分からないので対象外（従来どおり採点時に読み上げる）。
- ✅ **即時判定モードで、途中で間違えても最後まで並べれば正解に数えていた**: 間違えたタイルはその場で弾かれるので、何度間違えても最後には必ず盤面が完成し、全問間違えても「10/10」になっていた。`GameScreen` に問題ごとの `missedThisQuestion` を持たせ、間違えたタイルを置いたあとに完成させた場合は `status: 'fixed'` として扱うようにした。**得点・正解数・コンボは入らず**、成長記録では（同じランでその問題をあとで間違えずに解き直さない限り）「正解できなかった」に数える。ライフ・復習キュー・文法の集計は間違えた時点で記録済みなので二重には引かない。画面には「完成！でも まちがえたので正解には数えないよ」と出し、正解時の紙吹雪や不正解時の赤いフラッシュは出さない。
- **英検グレードとの整合性**: レベル名が英検4級〜2級を明示しているため、実際の出題範囲・文法項目との齟齬は信頼低下に直結する。

## 3. UI/UX（子ども向け）

- **タップ操作の一貫性**: ドラッグ&ドロップでなくタップ配置/削除方式。スロット同士のスワップができず、1語だけ間違えた時の修正が面倒。（UXの根本的な変更になるため、キッズ向けの分かりやすさを損なわないか要検証してから着手する）
  - ✅ 根本原因は「スロットが全部埋まった瞬間に即採点される」ことだった（間違いに気づいた時にはもう不正解が確定していた）。`GameScreen.tsx` に `CONFIRM_GRACE_MS`（650ms）の確認猶予を追加し、最後のタイルを置いても即座には採点せず、その間にどれかの解答欄をタップすればタイルをトレイに戻して直せるようにした（採点はキャンセルされる）。直さなければ猶予後に自動で採点される（すぐ確信が持てる子のテンポは大きく変えない）。スロット同士を直接入れ替える専用ジェスチャーはまだ無く、直すには一度トレイに戻して置き直す必要がある。
  - ✅ **ドラッグ&ドロップを追加（タップ操作はそのまま）**: トレイの単語を解答欄へドラッグで置ける。一発勝負モードでは、埋まっている欄に落とすと元の単語がトレイに戻って入れ替わり、置いた単語を別の欄へドラッグで移動・入れ替え、解答欄の外へドラッグでトレイに戻せる。やり直しモードは置いた単語が常に正解なので、ドロップ先は常に「次の欄」。落とし先は解答欄エリアのどこでも最寄りの欄に吸着するので、ピッタリ狙わなくてよい。8px動くまではタップ扱い。縦持ち（キャンバスをCSS回転）でも指に追従するよう、`src/utils/motion.ts` の `toCanvasDelta()` で画面座標をキャンバス座標に変換している。
- ✅ **遊びにくさの除去**: (1) 最初の単語を置いた瞬間に操作ボタン行が現れてトレイが下にズレていた（次のタップ位置がずれる）ので、`.actionRow` に常時高さを確保。(2) 正解/不正解後の待ち（最短1.1/1.5秒＋英語読み上げ完了まで）をタップ（PCはEnter/Space）でスキップ可能に。誤タップで結果を見逃さないよう、正解0.25秒・不正解0.7秒は受け付けない。(3) 戻る/やめるは1回目で赤く「もう一度タップでやめる」になり、2回目で確定（2.5秒で解除）。何も置いていない1問目は1タップで戻れる。(4) タップ領域: 単語タイルは最小38px＋周囲の隙間まで届く透明な当たり判定、HUDの戻る/やめるは最小40px、全て戻す/1つ戻す/これでOKは最小36pxでトレイから離した。やめるボタンの文字が小さい画面で6px台まで縮んでいたのを修正。(5) 長押しでのコールアウト抑止。
- ✅ **手触り・気持ちよさ**: 単語がトレイ⇄解答欄を飛んで移動するFLIPアニメーション（着地でわずかに潰れる）、置くたびに音程が上がるペンタトニックの効果音、コンボで半音ずつ上がる正解ファンファーレ、PERFECT!/GREAT!/GOOD!/CLEAR!（ミスがあった問題）の判定表示、TIME UP!/おしい！、正解時の単語ウェーブ、スコアのカウントアップ、コンボ数のバンプ、コンボに応じて画面の縁が温まる演出、失ったハートの演出、次に入る欄の点滅ガイド、Android向けの軽い振動（`src/utils/haptics.ts`）。reduced-motion ではアニメーションを止める。
- ✅ **キーボード操作**: 1〜9,0でトレイのN番目を置く（マウス環境ではタイル左上に番号を表示）、Backspaceで1つ戻す、Escで全て戻す、Enterで確認猶予中の決定/結果のスキップ。
- ✅ (#30) **確認猶予中もタイマーが動いていた**: 一発勝負モードで全スロットを埋めた後の `CONFIRM_GRACE_MS`（650ms）は「置き間違いに気づくための時間」であって「解くための時間」ではないのに、その間もカウントダウンが進み、正解しているのに時間切れとして採点され得た。タイマーの `useEffect` の停止条件に `awaitingConfirm` を追加した。
- ✅ (#17) **タイル一覧の位置ズレ**: タップして単語を置くたびに、`tray` 配列から要素を削除していたため残りのタイルが再センタリングされて位置がズレ、連続タップしづらかった。`tray` はレベル/問題が変わるまで並び順を固定したままにし、配置済みのタイルは配列から消す代わりに `opacity: 0; pointer-events: none;`（`WordTile.tsx` の `placed` prop）で見た目だけ消してレイアウト上の場所を保持するようにした。Playwrightで、中間のタイルをタップしても他のタイルの座標が変わらないことを確認済み。
- **読みやすさ**: 高校レベルの長い構文でタイル行が画面幅に収まるか、小画面端末での実機確認が必要。
- ✅ (#32) **色のみに依存した状態表現**: タイマーバーの緊急度が色変化（緑→黄→赤）だけで表されており、その区別がつかないプレイヤーには何も伝わっていなかった。バーの左に残り秒数（`role="timer"`）とアイコンを併記し、⏱️（通常）→ ⏳（warn: 残り40%以下）→ ⚠️（urgent: 残り4秒以下）と**色・形・数字の3チャンネル**で同じ情報を出すようにした。`aria-live="off"` で毎秒の読み上げ爆発は避けている。
- ✅ (#4, #5, #30) **モーション過多への配慮**: `prefers-reduced-motion` 時に、シェイク・フラッシュ・コンフェッティ・タイマー緊急パルス・コンボ炎アイコン・確認ボタン (#4, #5) に加えて、残っていた無限ループ4つも止めるようにした (#30): タイトルの10問チャレンジボタンの脈動とロゴタイルの浮遊（`TitleScreen.module.css`）、レベルカードのアイコン浮遊（`LevelSelect.module.css`）、結果画面のNew Bestの脈動（`ResultScreen.module.css`）。一度きりで静止する `pop-in` の登場アニメーションは意味を持つので残してある。
  - 副作用として、Playwrightが脈動中のボタンを「静止しない要素」と見なしてクリックできない問題があった。reduced-motionをエミュレートしないテストでは依然クリックできないので、タイトル画面を操作するテストは `eval` でクリックする必要がある。

## 4. アクセシビリティ

- ✅ (#13) **スクリーンリーダー対応**: タイル/スロットはネイティブ `<button>` なのでキーボード操作・読み上げの基本は元から効いていたが、`aria-label` を追加してより分かりやすくした（単語タイルは「{word} を置く」、解答欄は「解答欄 N：{word}。タップで取り消し」、空欄は「解答欄 N：空」）。タイル列・解答欄にも `role="group"` + `aria-label` を付けてグループとして認識できるようにした。
- **キーボード操作**: `<button>` ベースなのでTab移動＋Enter/Spaceでの操作は元から可能。
- **音声のみに頼らない設計**: 日本語プロンプト読み上げはSFXオン時のみ発火。音を出せない環境（学校・図書館）や聴覚障害のある子どもでも、視覚情報だけで完結するか（現状、単語タイル自体は常にテキスト表示なので大きな問題はなさそう）。

## 5. 音声・TTS（Web Speech API依存の弱さ）

- ✅ **正解時のみの読み上げ**: 従来 `speakEnglish()` は正解した時にしか発火せず、間違えた問題の正しい発音を聞く機会がなかった。`GameScreen.tsx` の `resolve()` で不正解時にも読み上げるようにし、「正解: ...」のテキスト表示と合わせて音でも正しい語順・発音を復習できるようにした。
- **端末依存の音声品質**: `src/audio/speech.ts` はブラウザ内蔵TTSに依存。`isSpeechSupported()` で非対応環境は静かにno-opになる設計は既にできている（テキスト表示は常にあるのでフォールバックとして十分）。
- ✅ (#29) **発話完了イベントの取りこぼしでゲームが止まる**: `speak()` が返す Promise は `onend`/`onerror` でしか解決せず、しかもこの Promise がゲーム進行を握っていた（日本語プロンプト読み上げ完了まで**タイマーが始まらない**／英語読み上げ完了まで**次の問題に進まない**）。Chromeは発話中のバックグラウンド化などで `end` イベントを落とすことがあり、その場合リロード以外に復帰手段のないフリーズになっていた。`SPEECH_TIMEOUT_MS`（10秒）のタイムアウトを追加し、時間切れなら `synth.cancel()` してから解決するようにした。二重解決しないこと・正常終了時にタイマーを片付けることも含めて `speech.test.ts` でカバー。
- **iOS Safariの制約**: `soundEngine.ts` の `unlock()` はユーザー操作（`onPointerDown`）から呼ばれており（`App.tsx`）、対応済み。
- **SFXのリアルタイム合成負荷**: 低スペック端末でのカクつきの可能性は未検証。

## 6. PWA・技術基盤

- **強制横画面のフォールバック**: `src/hooks/useForcedLandscape.ts` はCSS回転＋Screen Orientation API併用（良い設計）。iOS Safariは`orientation.lock`非対応、アプリ内ブラウザ（LINE/Instagram等）での見え方も確認。
- ✅ (#4, #5) **バックグラウンド時のタイマー**: `visibilitychange` を監視し、タブ非表示中はカウントダウン（インターバル）と正解後の自動遷移（`setTimeout`）の両方を一時停止するようにした。
- ✅ **PWA更新戦略**: 旧設定の `registerType: 'autoUpdate'` は新しい Service Worker を即座に有効化するだけで、開いているページは古いJSのまま動き続けた。全画面PWAは何日もバックグラウンドに置かれてナビゲーションが起きないため、ブラウザ側の更新チェック自体もほとんど走らず、新しい問題や修正がなかなか届かなかった。`registerType: 'prompt'` に変え、新版のダウンロード後は `src/utils/updateGate.ts` が「失うものがない時」まで再読み込みを待たせる: タイトル画面ならその場で、レベル選択・成長記録ならアプリがバックグラウンドに回った瞬間（見ていない間に読み込み直し、戻るとタイトル）。プレイ中と結果画面では適用しない（スコア・ライフ・未読の結果を失わないように）。また前面に戻るたびに最大1時間に1回 `registration.update()` で更新を確認する（`src/pwa/registerUpdates.ts`）。Playwrightで「レベル選択中に新版が届いても再読み込みされない → タイトルに戻ると新版に切り替わる」を確認済み。既存ユーザーは旧版のページに更新処理が無いので、この版だけは次回のアプリ起動時に切り替わる。
- **オフライン完結**: 効果音はWeb Audio合成でオフライン完結。ただしTTSはOS内蔵音声依存のため厳密には非オフライン。
- ✅ (#15) **セーフエリア対応**: `src/styles/global.css` の `.app-canvas` に、向き別に物理→視覚エッジを変換する `--safe-top/right/bottom/left` カスタムプロパティを追加。`is-landscape` は1:1、`is-portrait`（CSS回転中）は `rotate(90deg)` の回転方向を数式で導出し、物理top→視覚left、物理right→視覚top、物理bottom→視覚right、物理left→視覚bottomの対応で `env(safe-area-inset-*)` を割り当てた。各画面の `.screen` に `padding: var(--safe-top) var(--safe-right) var(--safe-bottom) var(--safe-left)` を適用（ノッチなし端末では全て0pxなので既存レイアウトに影響なし）。iPhone実機で確認済み — 方向は正しかった。

- ✅ (#7) **自動テストの不在**: Vitest導入済み（`npm test`）。`questionGen.ts`（`q()`）、`questions.ts`（`pickQuestions()`、全レベルの問題バンクのデータ整合性）、`storage.ts`（ベストスコアの保存/取得ロジック）をカバー。

- ✅ (#30) **lint警告の常態化**: 8件の警告が出っぱなしで、新しい警告が埋もれる状態だったので0件にした。
  - `react(purity)`（`Confetti.tsx`、6件）: レンダー中に `Math.random()` を呼んでいた。`useState` の遅延初期化に移し、マウント時に1回だけ抽選するようにした。コンポーネントは問題ごとに `key` で作り直されるので、新しい紙吹雪が要るときは再マウントされる。
  - `react(only-export-components)`（3件）: コンポーネントと非コンポーネントを同じモジュールから export していると React Fast Refresh が効かない。`estimateTileWidth` を `components/tileWidth.ts` に、コンテキスト本体とフックを `context/sound.ts` / `context/settings.ts` に分離し、`SoundContext.tsx` / `SettingsContext.tsx` はプロバイダだけを export するようにした。ファイル名の大文字小文字だけが違う名前（`soundContext.ts`）は、Windows/macOSの大文字小文字を区別しないファイルシステムで `SoundContext.tsx` に解決されてしまうため避けている。

- ❌調査済み（対応しない）**バンドルに全1,600問が同梱**: `dist/assets/index-*.js` は334kB（gzip 105kB）で、その大半が問題バンク。レベル別に動的importすれば初回パースは軽くなるが、**このアプリでは意味がない**。`vite.config.ts` のworkbox設定が `globPatterns: ['**/*.{js,css,html,png,svg,ico,woff2}']` で全JSチャンクをプリキャッシュするため、分割してもService Worker導入時に結局すべてダウンロードされる。プリキャッシュ対象から外せば初回は軽くなるが、未訪問のレベルがオフラインで遊べなくなる。オフラインで完結することの方がこのアプリには重要なので、現状維持とする。
- **多端末での実機QA必須**: 横画面固定・フルスクリーン・音声合成など多くのブラウザAPIに依存するため、Android Chrome / iOS Safari / 低スペック端末での実機確認が欠かせない（CIではカバーできない領域）。
